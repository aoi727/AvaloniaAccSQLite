# ReligiousReportApp 仕様書

## 1. 文書の目的
本書は `ReligiousReportApp` の機能仕様、データ構成、運用上の前提を整理したものです。実装基準日は 2026-05-12 時点のリポジトリ内容です。

## 2. システム概要
- 種別: Windows デスクトップアプリケーション
- UI: Avalonia
- データベース: SQLite
- 対象: 寺院、教会などの宗教法人向け運営収支報告
- 位置づけ:
  - `AccountingApp` の基本会計DBを参照する別プロジェクト
  - 既存会計テーブルは読み取り専用
  - 宗教法人向けの追加設定だけを `religious_report_*` テーブルに保存する

## 3. AccountingApp との関係
- `AccountingApp` が作成した SQLite DB ファイルを選択して利用する。
- 参照する主な既存テーブル:
  - `companies`
  - `accounts`
  - `journal_vouchers`
  - `journal_lines`
- 追加・更新するテーブル:
  - `religious_report_categories`
  - `religious_report_account_roles`
  - `religious_report_cash_flow_split_overrides`
  - `religious_report_cash_flow_overrides`
  - `religious_report_period_reviews`
  - `religious_report_carryovers`
  - `religious_report_notes`
  - `religious_report_budgets`
  - `religious_report_account_mappings` は旧方式互換用に残す
- `AccountingApp` 側のソースコード、スキーマ、画面は変更しない。
- `AccountingApp` は `religious_report_*` テーブルを使用しない。

## 4. 基本コンセプト
運営収支報告書は、損益科目だけを単純集計するのではなく、現金・預金の入出金を起点に作成する。

例:
- `現金 / 借入金` は現金が増えるため、報告書上は収入として扱える。
- `現金 / 預り金` は一時的な預りであり、報告書対象外にできる。
- `未払費用 / 現金` は現金支出時点で支出にできるが、分類判断が必要な場合はレビュー対象にする。

このため、本アプリは次の流れを採用する。
1. AccountingApp で通常どおり仕訳を入力する。
2. ReligiousReportApp でDBを開く。
3. 勘定科目に「現金・預金」「借入金」「預り金」「通常収入」「通常支出」などの役割を設定する。
4. 月次など任意期間で入出金レビューを行う。
5. レビュー済みの内容をもとに報告書プレビューを作成する。
6. 年度末には同じ仕組みで年度報告書を作成する。

## 6. 機能仕様
### 6.1 DB選択
- `DBを開く` から AccountingApp の SQLite DB を選択する。
- 対応拡張子:
  - `.db`
  - `.sqlite`
  - `.sqlite3`
- DB選択後、以下を行う。
  - 会社情報を取得する
  - `religious_report_*` テーブルを自動作成する
  - 初回のみ既定の運営収支分類を投入する
  - 既存勘定科目から科目役割を推定して初期投入する
  - 当年度と当月を初期表示期間に設定する

### 6.2 収支分類マスタ
宗教法人向けの運営収支報告書に表示する分類を管理する。

入力項目:
- 分類コード
- 分類名
- 区分: `income` / `expense`
- 表示順

初期投入される代表分類:
- 収入: お布施・献金収入、会費・維持費収入、寄付金収入、墓地・納骨堂収入、行事収入、借入金収入、その他収入
- 支出: 宗教活動費、人件費、寺務・事務費、維持管理費、行事費、その他支出

### 6.3 科目設定
AccountingApp の有効な勘定科目に、運営収支報告書用の役割と標準分類を設定する。

役割:
- `cash`: 現金・預金。入出金抽出の起点。
- `income`: 通常収入。相手科目として現れた場合、標準分類に収入計上する。
- `expense`: 通常支出。相手科目として現れた場合、標準分類に支出計上する。
- `borrowing`: 借入金。現金増加時は収入扱いにできる。
- `deposit`: 預り金・対象外。原則として報告書対象外。
- `payable`: 未払金・要確認。現金支出時に内容確認が必要。
- `receivable`: 未収入金・要確認。現金入金時に内容確認が必要。
- `excluded`: 対象外。
- `manual`: 毎回確認。

初期推定:
- 勘定科目名に `現金`、`預金`、`当座`、`小口` を含む場合は `cash`。
- `借入` を含む場合は `borrowing`。
- `預り`、`源泉`、`仮受` を含む場合は `deposit`。
- `未払`、`買掛` を含む場合は `payable`。
- `未収`、`売掛` を含む場合は `receivable`。
- `account_type = revenue` は `income`。
- `account_type = expense` は `expense`。
- その他は `excluded`。

### 6.4 入出金レビュー
任意の開始日・終了日を指定して、現金・預金科目の明細を一覧表示する。複合仕訳の場合は、現金・預金明細に対応する相手明細ごとにレビュー行を分解する。

例:

```text
給与手当   230,000 / 普通預金     200,000
                    / 源泉預り金    30,000
```

この場合、レビュー画面では次の2行として扱う。

- `給与手当 230,000`: 人件費として報告書に載せる。
- `源泉預り金 30,000`: 預り金として対象外にする。

表示項目:
- 日付
- 伝票番号
- 摘要
- 入金 / 出金
- 金額
- 現預金科目
- 相手科目
- 判定
- 分類
- メモ

判定:
- `報告書に載せる`: 指定分類へ集計する。
- `対象外`: 集計しない。
- `要確認`: プレビュー上の要確認件数に含める。

期間レビュー:
- 期間ごとに `仮`、`確認済み`、`確定` の状態を保持できる。
- 画面操作では `確認済み` と `確定` に対応する。
- 月次、四半期、年度途中など任意期間の仮出力に使える。
- 決算確定前は AccountingApp 側の仕訳修正を許容する。
- レビュー保存時に元仕訳のスナップショットとハッシュを保存する。
- 再表示時に現在の仕訳ハッシュと保存時ハッシュが違う場合、`変更あり` として表示する。
- `変更あり` の明細は報告書集計から除外し、要確認件数に含める。
- `変更あり` の明細は、レビューを保存し直すことで現在の仕訳内容として再確認済みにできる。
- `確定` した期間はレビュー結果を変更できない。
- `確定` は、要確認または変更ありの明細が残っている場合は実行できない。
- `確定解除` により、確定済み期間を `確認済み` に戻せる。
- 確定解除後はレビュー結果を再編集できる。

### 6.5 年度予算
- 年度開始日を指定して、分類別の年額予算を入力する。
- 予算は分類単位で保持する。
- 予算情報は `religious_report_budgets` に保存する。
- 報告書プレビューが年度未満の期間の場合、対象月数に応じて年額予算を按分表示する。

### 6.6 前期繰越・次期繰越
- 年度ごとに期首の繰越収支差額を入力する。
- 年度全体の報告書では、期首繰越を `前期繰越収支差額` として表示する。
- `次期繰越収支差額` は `前期繰越収支差額 + 当期収支差額` で計算する。
- 前年の年度期間が `確定` 済みの場合、前年の `次期繰越収支差額` を翌年度の期首繰越収支差額として自動作成できる。
- 自動作成時は、翌年度の既存期首繰越収支差額を作成結果で上書きする。
- 任意期間の仮出力では、期首繰越に年度開始日から期間開始日前日までの確認済み収支を加味し、期間開始時点の繰越額として表示する。
- 変更あり、要確認、分類未設定の明細は繰越計算にも含めない。

### 6.7 運営収支報告書プレビュー
- 入出金レビューの内容をもとに、任意期間の運営収支報告書を画面表示する。
- PDF出力に対応する。
- 画面プレビューはPDF出力に近い固定様式で表示する。

帳票ヘッダ:
- 表題: `運営収支報告書`
- 対象期間: `自 yyyy年M月d日 至 yyyy年M月d日`
- 法人名

表示項目:
- 前期繰越収支差額
- 分類コード
- 分類名
- 期間予算
- 実績額
- 差異
- 次期繰越収支差額
- 注記

集計行:
- 収入の部
- 収入合計
- 支出の部
- 支出合計
- 当期収支差額

集計仕様:
- 実績額は、現金・預金科目の明細のうち `報告書に載せる` 判定で分類が設定されたものを集計する。
- 入金は収入分類、出金は支出分類として扱う前提だが、最終的にはレビューで選択された分類に従う。
- `対象外` は集計しない。
- `要確認` または分類未設定は集計せず、要確認件数として表示する。
- 差異は `期間予算 - 実績額` とする。
- 当期収支差額は `収入合計 - 支出合計` とする。
- 次期繰越収支差額は `期間開始時点の繰越収支差額 + 当期収支差額` とする。
- 注記は期間単位で保存し、帳票末尾に表示する。

## 8. 制約事項
- `AccountingApp` の基本会計機能は本アプリに含まない。
- 仕訳入力、勘定科目登録、取引先管理は `AccountingApp` で行う。
- 本アプリは `religious_report_*` 以外のテーブルを更新しない設計とする。
- 複合仕訳は相手明細ごとに分解してレビューする。ただし、1つの伝票に複数の現金・預金明細と複数の相手明細が混在する高度なケースでは、実務上の確認が必要。
- 前年確定データからの自動繰越作成は、前年の年度期間と一致するレビュー状態が `確定` の場合のみ実行できる。
- 会計区分別、部門別の集計は未実装。
